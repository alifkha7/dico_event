# Multi-App Domain Architecture (`apps/*`) and Deep Module Boundaries

To eliminate horizontal tier fragmentation across a single monolithic `api` app and establish high locality per domain concept, the codebase replaces `api/` with five domain-aligned Django apps (`apps.users`, `apps.events`, `apps.tickets`, `apps.registrations`, `apps.payments`) and one shared infrastructure app (`apps.core`), registered under short app labels (`users`, `events`, `tickets`, `registrations`, `payments`, `core`) with `AUTH_USER_MODEL = "users.User"`. All underlying PostgreSQL table names (`db_table` values `users`, `events`, `event_posters`, `tickets`, `registrations`, `payments`) and public `/api/` route contracts (aggregated via `apps/core/urls.py`) remain unchanged so external clients and the Postman test suites require zero adjustments.

Inside these apps, cross-cutting mechanics are deepened behind narrow module seams:
1. **`apps.core`**: Owns `DualKeyModelSerializer` (declaratively resolving and emitting `<field>` and `<field>_id` foreign keys), `RoleOwnershipPermission` (centralizing ADR-0001 unauthenticated detail `retrieve`, Superuser/Admin access, and Organizer/User ownership rules), `PartialUpdateMixin`, `custom_exception_handler`, and `setup_logging`.
2. **`apps.events`**: Co-locates `Event` and `EventPoster` with `CachedEventViewSetMixin` (encapsulating Redis list/detail caching, `X-Data-Source` header tagging, and mutation invalidation) and `attach_event_poster` (encapsulating Organizer ownership verification, 500 KB + Pillow validation, MinIO object upload via `upload_poster_to_minio`, and `EventPoster` persistence).
3. **`apps.registrations`**: Folds resilient 2-hour pre-Event reminder scheduling (`schedule_event_reminder` / `send_event_reminder_email`) directly into the `Registration` creation lifecycle (`RegistrationSerializer.create`) so any registration creation honours the reminder invariant without inline task orchestration in HTTP views.
