# Production Security, Transactional Integrity, and Environment Separation

Following completion of the Dicoding Academy #788 submissions (preserved in Git history via tag `v2.0-dicoding-submission`), DicoEvent supersedes the autograder-specific workarounds in ADR-0001 in favor of production-grade access control, relational audit protection, domain quota invariants, presigned media URLs, and environment-separated configuration:

1. **Scoped RBAC Read & Mutation Policies**: Unauthenticated `GET` access remains public only for catalog endpoints (`Event`, `EventPoster`, `Ticket`). `User` detail (`retrieve`) requires self or `Admin`/`Superuser` access (`list` remains `Admin`/`Superuser`-only). `Registration` and `Payment` `list` and `retrieve` endpoints require authentication and scope visibility to the owning `User`, the `Organizer` of the parent `Event` (read-only), or `Admin`/`Superuser` (union-scoped when a `User` is also an `Organizer`).
2. **Financial & Transactional Audit Protection (`PROTECT` + Immutable Settlements)**: Foreign keys across `Ticket.event`, `Registration.ticket`, `Registration.user`, and `Payment.registration` use `on_delete=models.PROTECT`, surfacing `409 Conflict` via `custom_exception_handler` when callers attempt to delete records backed by transactional history. `Payment` statuses are restricted to `Pending`, `Completed`, `Failed`, and `Refunded` (`Refunded` restricted to `Admin`/`Superuser`), duplicate `Completed` payments per `Registration` are rejected, `amount_paid` must equal `Ticket.price` (including `0` for free tickets), and `Completed` or `Refunded` payments reject `DELETE` with `409 Conflict`.
3. **Strict Quota Allocation & Atomic Registration Intake**: Each `(User, Ticket)` pair allows at most one `Registration` (`UniqueConstraint`), total `Ticket.quota` across an `Event` cannot exceed `Event.quota` (`SUM(tickets.quota) <= Event.quota`), and `Registration` creation locks the target `Ticket` and `Event` rows (`transaction.atomic()` + `select_for_update()`) while enforcing the active `sales_start <= now <= sales_end` window.
4. **Presigned Poster URLs & Explicit CORS**: `EventPoster` responses retain `image` (object key) and expose `image_url` signed locally via `MINIO_PUBLIC_ENDPOINT_URL` (falling back to `MINIO_ENDPOINT_URL`, 1-hour default TTL, graceful `None` fallback on signing error) so URLs resolve cleanly across both host browsers and Docker networks. `django-cors-headers` enforces explicit `CORS_ALLOWED_ORIGINS` (placed immediately after `WhiteNoiseMiddleware`).
5. **Modular Settings (`dicoevent/settings/{base,dev,prod,test}.py`)**: Configuration splits into `base`, `dev`, `prod` (`DEBUG=False`, fail-fast `ImproperlyConfigured` on missing/insecure `SECRET_KEY` or `ALLOWED_HOSTS`, configurable HTTPS/cookie/HSTS headers), and `test` (in-memory SQLite and `LocMemCache` by default while honoring `USE_SQLITE_TEST=False` for PostgreSQL/Redis CI).
